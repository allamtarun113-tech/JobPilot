# Vercel dashboard deployment

The dashboard entrypoint is `app:app`, configured in `pyproject.toml`.
The root `app.py` adds `src/` to the import path before loading the dashboard. `vercel.json` selects FastAPI. `.vercelignore` keeps local secrets, private user data,
reference books, caches and tests out of uploads. The function retains source,
configuration, prompts and UI templates. Worker/dispatcher processes stay on the laptop.

## Prerequisites

On the laptop, set `DATABASE_URL` to the Supabase session pooler URL, using
`postgresql+psycopg://`. Keep the dedicated test database separate. Before applying
migrations to Supabase, inspect the migration files, confirm the target and back up any
existing data. Local profile data is not automatically copied to the cloud database.

In Vercel project environment variables, configure:

- `JOBPILOT_ENV=prod`
- `DATABASE_POOLER_URL`: Supabase transaction pooler URL, with `postgresql+psycopg://`
- `DATABASE_URL`: the same cloud project's session connection, never localhost
- `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_STORAGE_BUCKET=jobpilot`
- `DASHBOARD_TOTP_SECRET` and a stable `DASHBOARD_SESSION_SECRET`
- `DASHBOARD_BASE_URL`: the deployment's HTTPS URL
- `OPENAI_API_KEY`: enables enqueueing profile-note extraction; model work runs on the laptop

The platform sets `VERCEL=1`. Do not upload the entire laptop `.env` as a deployment file.
Add dashboard credentials through server environment variables. Gmail, Telegram, search,
MCP and approval-token credentials belong to the laptop worker/dispatcher.

## Deploy and verify

Sign in with `npx --yes vercel login`, then link the intended existing project or create
`jobpilot` under the correct account. Use the free personal plan when applicable; do not
upgrade or buy integrations. Add the environment variables before publishing. A preview
should pass login, authenticated database reads and private PDF access before production
promotion. Test private pages without a session and ensure they redirect to login.

Enroll the existing `DASHBOARD_TOTP_SECRET` from local `.env` in an authenticator as a
manual Base32 time-based key. Treat the secret like a password; do not regenerate it
while the deployed environment still uses the old value.

Run `make check` before publishing. Cloud migrations, private bucket creation, account
sign-in, live provider validation and data migration are separate steps; merely having
keys present does not verify them. Keep `shadow_mode: true` throughout rollout. Connect
Gmail only after replacing any secret shared in chat with a rotated value in local `.env`.

## Deployment verified on 2026-10-05

Dashboard: https://jobpilot-tharun-f923.vercel.app. The root entrypoint was verified
against Vercel's runtime; all 225 local regression tests pass. Live database health,
unauthenticated redirects, TOTP login and the profile/resume/preferences/jobs/runs pages
passed. The Supabase schema was initialized in an empty public schema and RLS enabled
on all 30 tables. Private storage remains configured. No paid model calls or emails
were generated by deployment verification.

Vercel account protection remains enabled alongside JobPilot login. Authenticator
setup instructions are in the private, upload-excluded `Data/user/dashboard-login.txt`.
Worker and dispatcher are not hosted on Vercel. Telegram needs an owner conversation
before `TELEGRAM_CHAT_ID` can be set; Gmail still needs the local authorization flow.
Web search runs on the OpenAI key (decision 21). The cloud profile starts empty;
local profile/resume records were not automatically transferred or confirmed.

Login forms and dashboard responses use `Cache-Control: no-store`. Session cookies
use SameSite=Lax so top-level navigation from Vercel sign-in can retain the session;
all POST routes still enforce CSRF. A rejected login CSRF submission redirects to a
fresh form with an expiry message and never authenticates the submitted code.

Job details show original/tailored resume keyword scores, covered/missing keywords,
exact before/after wording, both private PDF links when available, the resume review,
and curated learning resources for skill gaps.
Confirmed-profile job fit is separate and does not increase through wording changes.
The deployment includes `Data/learning` and `Data/taxonomy`; private `Data/user`,
books, reports and runtime credentials remain excluded.
